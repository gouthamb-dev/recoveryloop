# Infrastructure Unit — Domain Entities

## Overview
The infrastructure unit has no business logic. Its "domain" is the AWS resource model
and the DynamoDB data schema that the backend-lambda unit depends on.

---

## DynamoDB Table: RecoverySessions

### Table Definition
- **Table Name**: `RecoverySessions`
- **Partition Key**: `sessionId` (String) — UUID v4
- **Sort Key**: None (single-item per session)
- **Billing Mode**: PAY_PER_REQUEST (on-demand)
- **Encryption**: AWS-managed CMK (SSE enabled)
- **TTL Attribute**: `expiresAt` (Number — Unix epoch seconds)

### Item Schema

```
RecoverySessions Item
{
  sessionId       String   PK       UUID v4 — e.g. "a1b2c3d4-..."
  lastPrompt      String            The userPrompt from the most recent request
  lastScript      String            The raw script generated by Bedrock
  lastResult      Map      {
                             status:          "success" | "failure" | "timeout"
                             stdout:          String
                             stderr:          String
                             exitCode:        Number
                             executionTimeMs: Number
                           }
  lastUpdatedAt   String            ISO 8601 timestamp of last write
  expiresAt       Number            Unix epoch seconds — now + 86400 (24 hours)
}
```

### Access Patterns
| Operation | Key | Used By |
|---|---|---|
| GetItem | `sessionId` | SessionService.loadSession() |
| PutItem | `sessionId` | SessionService.saveSession() |
| (auto-delete via TTL) | `expiresAt` | DynamoDB TTL process |
